Case Study — MSP Client Work

Network Switch Replacement

Swapped out a production network switch by documenting every detail of the old configuration first, then mirroring it on new hardware for a cutover nobody noticed.

Networking Infrastructure Documentation

Problem

A client's core network switch needed replacing. The existing configuration — VLANs, port assignments, uplinks — had accumulated over time and wasn't fully documented anywhere. Getting it wrong meant knocking devices offline during business hours.

What I built

Before touching any hardware, I thoroughly documented the existing switch: every port, its VLAN membership, what was plugged into it, and the uplink topology. I then configured the replacement switch to mirror that setup exactly, verified the config offline, and performed the physical cutover in a maintenance window. The result was a seamless swap with no disruption to network services.

What I learned

The documentation step was the whole project. Once the port map and VLAN table existed, configuring the new switch was straightforward and the cutover was low-stress because there was nothing left to guess. It also left the client with documentation they didn't have before, which made every future change easier.
