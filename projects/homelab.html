Case Study — Personal Homelab

Proxmox Homelab

A repurposed Dell OptiPlex running Proxmox VE, hosting the VMs and containers I use to practice virtualization, DNS filtering, reverse proxying, and monitoring — the same building blocks I work with in client environments.

Proxmox VE LXC Pi-hole Nginx Proxy Manager Tailscale

Problem

At an MSP you touch virtualization, DNS, reverse proxies, containers, and monitoring every week — but usually in someone else's environment, under time pressure, and without room to break things. I wanted a place where I could build those pieces from scratch, understand how they fit together, and troubleshoot them when they fail.

What I built

The host is a Dell OptiPlex desktop with 32 GB of RAM and 512 GB of storage, running Proxmox VE. On top of it:

  • Home Assistant OS — a full VM that powers the apartment smart-home build.
  • Windows 11 — a test/lab VM for trying policies, software, and troubleshooting steps before touching a real machine.
  • Pi-hole (LXC) — network-wide DNS filtering and ad blocking.
  • Nginx Proxy Manager (LXC) — a reverse proxy so every internal service gets a clean hostname and TLS instead of an IP and a port number.
  • Portainer (LXC) — container management with a UI.
  • Uptime Kuma (LXC) — uptime monitoring and alerting for everything above.

Remote access runs over Tailscale, so I can reach the lab from anywhere without opening ports on the router.

Architecture

Stack & tools

  • Proxmox VE — hypervisor for both full VMs and lightweight LXC containers
  • Home Assistant OS — runs as a VM so it gets its own kernel and full add-on support
  • Pi-hole — DNS sinkhole for the whole network
  • Nginx Proxy Manager — reverse proxy with a UI for hostnames and TLS certs
  • Portainer — Docker/container management
  • Uptime Kuma — status page and alerts
  • Tailscale — WireGuard-based mesh VPN for remote access

What I learned

LXC vs VM is a real trade-off. Containers share the host kernel, so they start instantly and use a fraction of the RAM — perfect for small services like Pi-hole or Uptime Kuma. Anything that needs its own kernel, hardware passthrough, or a different OS (Home Assistant OS, Windows 11) has to be a VM. Picking the wrong one either wastes resources or hits a wall.

A reverse proxy simplifies everything behind it. Before Nginx Proxy Manager, every service was an IP and a port I had to remember. After, each one is a hostname with a valid certificate, and adding a new service is a two-minute job.

Uptime monitoring changed how I troubleshoot. Uptime Kuma tells me when something broke and roughly when — so instead of noticing an outage hours later and guessing, I can correlate it with what I changed. That habit carries directly into client work.
