Case Study — Personal Homelab

Home Assistant Apartment Build

A renter-safe smart home, staged deliberately: start with what works out of the box, then take control with Home Assistant running on the homelab.

In Progress
Home Assistant HomeKit Zigbee Matter MCP

Problem

I wanted a smart home I actually control — local automations, one dashboard, no dependence on a dozen vendor apps. The constraint that shaped everything: it's an apartment. No rewiring, no in-wall switches, nothing a landlord would notice. Everything has to be renter-safe and easy to pack up and move.

What I built

Home Assistant OS runs as a VM on the Proxmox homelab. Devices are all plug-in or battery: smart plugs, bulbs, and sensors instead of anything wired into the wall.

Staged plan: HomeKit → Home Assistant → Zigbee → Matter. I started with HomeKit because it works out of the box with the devices I already had and needed zero setup. Then Home Assistant became the hub so those same devices could be automated locally and shown on one dashboard. Zigbee is the next expansion — cheaper sensors and bulbs that don't need Wi-Fi — and Matter comes last, once more of the hardware I want supports it. Each stage builds on the previous one instead of replacing it.

Hardware researched: the Home Assistant Green as a standalone alternative to the VM, and the Home Assistant Connect ZBT-2 dongle for Zigbee and Thread radios.

Experiment: bridging Home Assistant to Claude via MCP

I also researched connecting Home Assistant to Claude Desktop through a local MCP (Model Context Protocol) proxy, so an AI assistant can read device state and trigger automations in plain language — "is the front door sensor open?" or "turn off everything in the living room." It runs entirely on the local network, and it's an experiment rather than a core piece of the setup, but it's a useful way to learn how AI tooling integrates with real systems.

Architecture

Stack & tools

  • Home Assistant OS — the hub, running as a VM for full add-on support
  • HomeKit — first stage, zero-setup integration with existing devices
  • Zigbee via Home Assistant Connect ZBT-2 — next expansion (Zigbee + Thread)
  • Matter — planned once device support catches up
  • Home Assistant Green — researched as a standalone alternative to the VM
  • MCP proxy → Claude Desktop — experimental AI bridge, local only

What I learned

Staging the build was the right call. Starting with HomeKit meant I had something working on day one, and moving to Home Assistant afterward was an upgrade rather than a rebuild. The apartment constraint also turned out to be a useful design filter — if a device needs a screwdriver, it's out.
